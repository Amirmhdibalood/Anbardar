پرامپت ادامه‌ی پروژه «انباردار» (Anbardar)
به‌روزرسانی: ۲۷ مهر ۱۴۰۵ (19 Oct 2026) — نسخه فعلی: 1.5.1 (versionCode 12)
=====================================================================
این فایل را کامل به یک دستیار هوش مصنوعی جدید بده تا کار بدون از دست رفتن چیزی ادامه پیدا کند.
مرجع کامل و به‌روز: README.md در ریشه‌ی مخزن (این فایل با آن هماهنگ است).

۱) نقش تو (دستیار)
- همیشه فارسی و ساده جواب بده؛ کاربر (امیرمهدی بلود) مبتدی است و کامپیوترش ضعیف است، پس همه‌ی ساخت‌ها روی
  ماشین خودت انجام شود و فقط فایل نهایی تحویل داده شود.
- مثل یک معمار ارشد نرم‌افزار رفتار کن: اگر تصمیمی اشتباه است، قبل از پیاده‌سازی بگو و دلیل بیاور.
- از گسترش بی‌جای کار (scope creep) پرهیز کن؛ فقط مرحله‌ی تأییدشده را انجام بده. این یک محصول واقعی است، نه دمو.
- هرگز رمز keystore، توکن گیت‌هاب، توکن ربات تلگرام یا chat id را چاپ، کامیت یا در فایل‌های مخزن ذخیره نکن.

۲) معرفی محصول
«انباردار» برنامه‌ی فارسی، راست‌به‌چپ و آفلاین انبارداری و حسابداری برای مغازه‌های کوچک: کالا، چند انبار و موجودی،
خرید، فروش، برگشت، انتقال، طرف حساب، دریافت/پرداخت، چک، هزینه، گزارش سود و زیان، کاربران و نقش‌ها، دوره‌های مالی، پشتیبان.
- شناسه: ir.anbardar.app — اول Android؛ معماری آماده‌ی وب، iOS و Windows.
- کاملاً آفلاین (مجوز INTERNET حذف شده)، بدون تبلیغ و حساب ابری، allowBackup=false.

۳) فناوری و معماری
- React 19 + TypeScript + Vite، React Router 7، CSS Modules، Capacitor 8 (minSdk 26 / target 36).
- SQLite: @capacitor-community/sqlite روی اندروید (پشتیبانی SQLCipher دارد ولی فعلاً 'no-encryption' باز می‌شود)،
  sql.js در وب و تست‌ها. پشتیبان = JSON کامل بدون رمز (روشن کردن رمزنگاری = پرسش باز).
- Migrationهای نسخه‌دار (src/database/migrations): 001 initial، 002 quantities_units، 003 cost_lots، 004 expenses،
  005 returns_transfers، 006 parties_money، 007 units_landed_cheques، 008 request_keys، 009 users_audit، 010 recovery_fiscal.
  فقط به انتها اضافه کن؛ قدیمی را ویرایش نکن؛ Snapshot قبل از اجرا؛ هر کدام در یک تراکنش.
- مبالغ عدد صحیح تومان؛ تعداد = هزارم واحد (عدد صحیح)؛ شناسه UUID v7؛ تاریخ ISO ذخیره و شمسی نمایش.
- دفتر حرکت stock_movements منبع حقیقت موجودی (فقط افزودنی)؛ warehouse_stock فقط کش.
- بهای FIFO با cost_lots + lot_allocations؛ روی ردیف فروش FIFO، میانگین و آخرین خرید ذخیره می‌شود.
- سند ویرایش نمی‌شود، فقط ابطال؛ رکورد استفاده‌شده فقط غیرفعال می‌شود؛ مانده طرف حساب از اسناد محاسبه می‌شود.
- دسترسی‌ها در لایه‌ی سرویس (services/secured.ts → guard): مجوز + اجرا + audit_log در یک تراکنش؛ UI فقط پنهان می‌کند.
- ثبت یک‌باره با request_id و ایندکس UNIQUE.
- ساختار: src/{components,config,database,hooks,layouts,models,navigation,pages,repositories/sqlite,routes,services,styles,utils,validation}،
  tests/*.test.ts، scripts/e2e-*.mjs (Puppeteer) و scripts/walkthrough.sh (ماتریس دستگاه).
