## ۱) انباردار چیست

«انباردار» یک برنامهٔ **آفلاین، فارسی و راست‌به‌چپ** برای **انبارداری و حسابداری مغازه‌ها و کسب‌وکارهای کوچک** است:
کالا و گروه کالا، چند انبار و موجودی، خرید، فروش، برگشت‌ها، انتقال بین انبارها، طرف حساب‌ها (مشتری/تأمین‌کننده)، دریافت و پرداخت، چک، هزینه‌ها، گزارش سود و زیان، کاربران و نقش‌ها، دوره‌های مالی و پشتیبان‌گیری.

- **اول برای Android** ساخته شده (شناسه `ir.anbardar.app`، حداقل Android 8 / API 26، هدف API 36).
- منطق برنامه از ظاهر جداست (صفحه ← سرویس ← مخزن)، پس **نسخهٔ وب، iOS و Windows** بعداً بدون بازنویسی منطق ساخته می‌شوند. همین حالا برنامه در مرورگر هم اجرا می‌شود (برای توسعه و تست).
- **کاملاً آفلاین**: مجوز `INTERNET` از Manifest حذف شده، `allowBackup=false` است، هیچ سرور، حساب ابری یا تبلیغی وجود ندارد.
- مالک پروژه: **امیرمهدی بلود** — مخزن: <https://github.com/Amirmhdibalood/Anbardar> (شاخهٔ `main`).
- این یک محصول واقعی است، نه دمو.

## ۲) فناوری و معماری

### فناوری‌ها
| بخش | ابزار |
|---|---|
| رابط کاربری | React 19 + TypeScript + Vite، React Router 7 (HashRouter)، CSS Modules + متغیرهای CSS؛ بدون Material UI (کامپوننت‌ها اختصاصی‌اند) |
| موبایل | Capacitor 8 (Android). افزونه‌ها: sqlite، app، filesystem، keyboard، share، system bars |
| دیتابیس | SQLite — روی اندروید `@capacitor-community/sqlite` (نسخه‌ای که از **SQLCipher** پشتیبانی می‌کند)، در مرورگر و تست‌ها `sql.js` (همان SQL و همان Migrationها) |
| فونت | Vazirmatn (پیش‌فرض)، Sahel، Samim — همه محلی داخل برنامه، مجوز OFL (`public/licenses`) |
| تست | `node --test` + `tsx` (تست واحد و یکپارچهٔ دیتابیس)، Puppeteer (e2e در Chrome بدون رابط) |

> ⚠️ **وضعیت واقعی رمزنگاری (مهم):** افزونهٔ SQLite امکان SQLCipher را دارد، اما در نسخهٔ 1.5.1 اتصال با `'no-encryption'` باز می‌شود (`src/database/drivers/capacitorDatabase.ts`) و فایل پشتیبان یک **JSON بدون رمز** است. حفاظت فعلی: پوشهٔ خصوصی برنامه + `allowBackup=false` + هش PBKDF2 برای رمزها. روشن کردن رمزنگاری دیتابیس و پشتیبانِ رمزدار در «پرسش‌های باز» (بخش ۵) آمده و باید با کاربر تصمیم گرفته شود.

### اصول معماری (همیشه رعایت شود)
- **مبلغ همیشه عدد صحیح و به تومان** (`utils/money.ts`). ارز دیگری نیست. ستون اعشاری (REAL) در دیتابیس نداریم.
- **تعداد = هزارم واحد، عدد صحیح** (۱٫۵ کیلو = `1500`) — `utils/quantity.ts`.
- **شناسه‌ها UUID نسخهٔ ۷** (`utils/id.ts → newId()`). تاریخ‌ها ISO 8601 ذخیره و **شمسی** نمایش داده می‌شوند.
- **دفتر حرکت کالا (`stock_movements`) منبع حقیقت موجودی است** و فقط افزودنی است. `warehouse_stock` فقط کش است و باید با جمع دفتر برابر باشد (`verifyConsistency` / `rebuildCache`).
- **بهای تمام‌شده FIFO** با لایه‌های بها (`cost_lots` + `lot_allocations`): هر خرید یک لایه؛ هر خروج از قدیمی‌ترین لایه برمی‌دارد. روی هر ردیف فروش سه بها ذخیره می‌شود: FIFO، میانگین متحرک، آخرین خرید؛ روش سود در تنظیمات (پیش‌فرض FIFO).
- **سند ویرایش نمی‌شود، فقط ابطال** (با دلیل). Triggerهای دیتابیس جلوی ویرایش و حذف ردیف‌های فاکتور و دفتر را می‌گیرند.
- **رکوردِ استفاده‌شده حذف نمی‌شود، فقط غیرفعال** (کلیدهای خارجی بدون `ON DELETE`).
- **مانده طرف حساب ذخیره نمی‌شود**؛ همیشه از اسناد محاسبه می‌شود.
- **دسترسی‌ها در لایهٔ سرویس اعمال می‌شوند** (`services/secured.ts` → `guard()`): بررسی مجوز، اجرای سرویس و ثبت در **گزارش فعالیت (audit log)** همه در **یک تراکنش**. متدی که در فهرست نیست رد می‌شود (امن به‌صورت پیش‌فرض). UI فقط دکمه‌ها را پنهان می‌کند (`useCan`) و هرگز نگهبان نیست.
- **گزارش فعالیت (`audit_log`) فقط افزودنی است** (Trigger جلوی UPDATE/DELETE را می‌گیرد).
- **ثبت یک‌باره (idempotent)**: هر فرم یک `request_id` دارد + ایندکس UNIQUE؛ دوبار زدن دکمه سند دوم نمی‌سازد.
- **UI منطق ندارد**: صفحه ← hook ← service ← repository (interface). درایور دیتابیس فقط در `database/open.ts` انتخاب می‌شود.
- **خطاها** به `AppError` با پیام فارسی تبدیل می‌شوند (`database/errorMapper.ts`)؛ جزئیات فنی فقط در کنسول.
- **مرتب‌سازی فارسی** با `Intl.Collator('fa')`؛ **جستجو** با یکسان‌سازی (`utils/search.ts`).

## ۳) تصمیم‌های طراحیِ تأییدشده توسط کاربر

این‌ها را **بدون اجازهٔ کاربر تغییر ندهید.**

### ظاهر و ناوبری
- **سربرگ:** عنوان سمت **راست**، دکمهٔ بازگشت سمت **چپ** (ثابت `BACK_BUTTON_SIDE='left'` در `config/ui.ts`). نوار بالای بومی اندروید حذف شده.
- **چراغ تم** بالا-چپ در خانه و تب‌های اصلی: چراغ **روشن = تم روشن**، **خاموش = تم تیره**. با لمس، تم با انیمیشن نرم عوض و ذخیره می‌شود.
- **زنگ** کنار چراغ فقط برای **اعلان‌های داخل برنامه** (چک سررسید، کم‌موجودی، پشتیبان)؛ اعلان سیستمی اندروید نداریم.
- **بنرهای شناور شبیه تلگرام** در خانه: بدون جابه‌جا کردن صفحه، حداکثر ۲ تا، با X یا کشیدن بسته می‌شوند و در زنگ می‌مانند؛ **هر مورد فقط یک بار** نمایش داده می‌شود.
- **۵ رنگ تأکیدی** (بنفش، فیروزه‌ای، زمردی، طلایی، زرشکی) جداگانه برای تم تیره و روشن. **بنفش رایگان** است؛ بقیه برچسب «ویژه» دارند و با پرچم `PREMIUM_ACCENTS_LOCKED` در `src/config/themes.ts` قفل می‌شوند (فعلاً `false`؛ در مرحلهٔ ۶ با پرداخت مایکت).
- **فونت:** Vazirmatn (پیش‌فرض)، Sahel، Samim — در تنظیمات ظاهری.
- **انتخابگرهای اختصاصی** (bottom sheet) به‌جای `<select>` بومی، با **جستجوی زنده**.
- **ورودی عددی مشترک** (`NumberInput` و MoneyInput/QuantityInput/PercentInput در `components/Field.tsx`): جداکنندهٔ سه‌رقمی زنده، ارقام فارسی، مکان‌نمای درست، **هرگز بریده نمی‌شود**. هر فیلد عددی جدید باید از این‌ها استفاده کند (فقط PIN و شمارهٔ چک متنی ساده‌اند).
- **لوگو و اینترو:** لوگو از **چپ** و نام از **راست** وارد می‌شوند (~۱٫۲ ثانیه، پس‌زمینهٔ سرمه‌ای `#0D122F`، بدون فلاش سفید).
- **نوار پایین:** خانه · کالاها · **دکمهٔ وسط «ثبت»** (برگهٔ عملیات: فروش، خرید، دریافت/پرداخت، ...) · گزارش‌ها · بیشتر.
  (کاربر این را «خانه/عملیات/کالاها/گزارش‌ها/بیشتر» نامیده؛ در کد فعلی برچسب دکمهٔ وسط «ثبت» است.)
- همهٔ صفحه‌ها در هر دو تم، تمام‌صفحه (100dvh، safe-area)، کیبورد فیلد را نمی‌پوشاند، دکمهٔ بازگشت سخت‌افزاری: اول برگهٔ باز بسته می‌شود، فرم دارای تغییر می‌پرسد، در خانه دوبار زدن = خروج.

### خرید، فروش و موجودی
- **قیمت واحد / مبلغ کل**: روی ردیف‌های خرید و موجودی اولیه قابل انتخاب است؛ در حالت «مبلغ کل» همان مبلغ دقیق ذخیره می‌شود. آخرین انتخاب به خاطر سپرده می‌شود.
- **واحد فرعی** با ضریب (مثلاً کارتن = ۲۴ عدد)؛ دفتر همیشه به واحد پایه.
- **هزینه‌های جانبی خرید** (حمل، بیمه، ...) به نسبت ارزش یا تعداد بین کالاها تقسیم و وارد بها می‌شوند؛ جزو بدهی به تأمین‌کننده نیستند.
- **قیمت خرید روی تعریف کالا نیست**؛ فقط روی فاکتور خرید. پیشنهاد قیمت فروش: دستی / آخرین فروش (پیش‌فرض) / آخرین خرید + درصد سود (سراسری یا گروه).
- **«تعریف کالای جدید»** از انتخابگر کالای فاکتور خرید و «ثبت موجودی اولیه کالا» (نه در فروش)، با نامِ تایپ‌شده؛ فاکتور حفظ می‌شود.
- **موجودی منفی به‌صورت پیش‌فرض ممنوع** (سرویس + Trigger).
- **هشدار «تمام شد»** فقط برای کالاهایی که **نقطهٔ سفارش** دارند.
- «کسری» و «ضایعات/خرابی» دو نوع حرکت جدا هستند.

### پول و طرف حساب
- طرف حساب یکپارچه (مشتری / تأمین‌کننده / هر دو)؛ «مشتری نقدی» و «متفرقه» سیستمی‌اند و نسیه ندارند.
- **دریافت و پرداخت می‌پرسد بابت کدام فاکتور**؛ اگر انتخاب نشود، **خودکار از قدیمی‌ترین فاکتور** کم می‌شود.
- **دکمهٔ «پس دادن طلب» (استرداد)** و وصول بدهی بدون فاکتور در صفحهٔ حساب طرف.
- **جهت پول قفل است**: در صفحهٔ بدهکار فقط «دریافت از او»، در صفحهٔ بستانکار فقط «پرداخت به او»؛ فرمِ باز شده از فاکتور هم قفل است؛ فرم عمومی هر دو را دارد ولی پیش‌فرضش از علامت مانده می‌آید.
- چک: دریافتی/پرداختی، وصول، برگشت (بدهی دوباره باز می‌شود)، خرج کردن چک.

### ایمنی داده
- **پیشنهاد پشتیبان هنگام خروج** (اگر تغییری بوده) و **هشدار پشتیبان در اولین اجرا**.
- **ثبت یک‌باره** (idempotent submit).
- **چاپ و PDF فاکتور** (برگهٔ اشتراک اندروید / دانلود در وب).

- **رمز (PIN) ۴ تا ۸ رقم**، هش PBKDF2-SHA256 (۱۲۰ هزار دور، نمک تصادفی). **۵ رمز اشتباه ← قفل ۳۰ ثانیه، هر بار دو برابر، حداکثر ۱۵ دقیقه.**
- **قفل خودکار پس از ۵ دقیقه** در پس‌زمینه (وقتی کاربران روشن است).
- **تنظیم «ورود با رمز»** (فقط مالک، با رمز مالک) می‌تواند ورود را خاموش کند؛ آن‌وقت برنامه به نام اولین مالک باز می‌شود و در گزارش فعالیت ثبت می‌شود.
- **آخرین کاربر به خاطر سپرده می‌شود** (فقط شناسه، هرگز رمز).
- **«رمز را فراموش کردم»** با دو سؤال امنیتی (پاسخ‌ها یکسان‌سازی و هش می‌شوند، همان قفل رمز اشتباه).
- آخرین مالک فعال قابل غیرفعال‌سازی یا تنزل نیست.

### دوره‌های مالی
- بستن **فقط بعد از پایان دوره** و **به ترتیب** (دورهٔ قبلی باز نباشد).
- با بستن، اسناد داخل دوره قفل می‌شوند (ثبت، ابطال یا تاریخ‌زدن داخل آن ممنوع) و **مانده طرف حساب‌ها، موجودی، لایه‌های FIFO و نقد** به دورهٔ بعد منتقل می‌شوند (Snapshot در `fiscal_balances`؛ سند مصنوعی ساخته نمی‌شود).
- **نقد = دریافت نقدی − پرداخت نقدی − هزینه‌ها** (هزینه‌ها نقدی حساب می‌شوند).
- **بازگشایی فقط آخرین دورهٔ بسته، فقط مالک**، با تأیید.

### ۶-۷) نوشتن Migration جدید
1. فایل `src/database/migrations/011_<نام>.ts` بسازید:
   ```ts
   import type { Migration } from './types'

   export const migration011: Migration = {
     version: 11,
     name: 'barcodes',
     statements: [
       `CREATE TABLE IF NOT EXISTS product_barcodes (
          id TEXT PRIMARY KEY,
          product_id TEXT NOT NULL REFERENCES products(id),
          barcode TEXT NOT NULL,
          created_at TEXT NOT NULL, updated_at TEXT NOT NULL, is_active INTEGER NOT NULL DEFAULT 1
        )`,
       `CREATE UNIQUE INDEX IF NOT EXISTS ux_product_barcodes ON product_barcodes (barcode) WHERE is_active = 1`,
     ],
   }
   ```
   هر عضو آرایه **دقیقاً یک دستور SQL** است. مبلغ و تعداد `INTEGER`؛ بدون `ON DELETE`.
2. در `src/database/migrations/index.ts` آن را import و **به انتهای** `MIGRATIONS` اضافه کنید.
3. جدول جدید را به پشتیبان اضافه کنید: `validateDump` در `src/database/snapshot.ts` (مثل خط `schemaVersion >= 10`).
4. اگر جدولی را بازسازی می‌کنید، Triggerهای مرتبط را قبلش حذف و بعدش دوباره بسازید.
5. تست بنویسید: ارتقا از دیتابیس دارای دادهٔ نسخهٔ قبل + پشتیبان/بازیابی (نمونه: `tests/stage5.test.ts`).
6. **Migration منتشرشده را هرگز ویرایش نکنید**؛ اصلاح = Migration بعدی.

   - یک تاریخ انقضا بگذارید؛ توکن را کپی و در مدیر رمز نگه دارید (دوباره نشان داده نمی‌شود).
2. ارسال:
   ```powershell
   git status                     # ببینید چه چیزی تغییر کرده
   git add -A
   git status                     # مطمئن شوید هیچ .apk / .jks / رمز / توکنی در فهرست نیست
   git commit -m "v1.6.0: توضیح کوتاه"
   git push origin main
   ```
   بار اول پنجرهٔ ورود باز می‌شود؛ نام کاربری `Amirmhdibalood` و به‌جای رمز، **توکن** را بدهید (Git Credential Manager آن را امن نگه می‌دارد).
3. **هرگز** توکن را داخل فایل، آدرس remote یا پیام کامیت ننویسید.

### ۶-۹) ارسال APK با ربات تلگرام @AppAnbardarbot
1. توکن ربات را از **@BotFather** بگیرید (`/mybots` → AppAnbardarbot → API Token). اگر لو رفت، همان‌جا **Revoke** کنید.
2. شناسهٔ چت (chat id): یک پیام به ربات بدهید، سپس در مرورگر `https://api.telegram.org/bot<TOKEN>/getUpdates` را باز کنید و `chat.id` را بردارید.
3. ارسال (توکن را فقط در همان پنجره در متغیر بگذارید):
   ```powershell
   $env:TG_TOKEN = "<توکن ربات>"
   $env:TG_CHAT  = "<chat id>"
   curl.exe -s -F "chat_id=$env:TG_CHAT" -F "caption=انباردار نسخه 1.6.0" -F "document=@F:\Anbardar\anbardar-v1.6.0-release.apk" "https://api.telegram.org/bot$env:TG_TOKEN/sendDocument"
   Remove-Item Env:TG_TOKEN
   ```
   پاسخ باید `"ok":true` داشته باشد. **هر نسخه فقط یک بار** ارسال شود (قبل از ارسال دوباره بررسی کنید قبلاً نرفته باشد).
4. توکن ربات **هرگز** کامیت یا در فایل پروژه ذخیره نشود.

2. **همراه هر نسخه فهرست تست‌ها و نتیجه‌شان** (و مسیر اسکرین‌شات‌ها) را به کاربر بدهید.
3. **تحویل از دو راه:** APK امضاشده از طریق ربات تلگرام + کد در گیت‌هاب (`main`). نام فایل: `anbardar-vX.Y.Z-release.apk`.
4. **هرگز** رمز keystore، توکن گیت‌هاب، توکن ربات تلگرام یا chat id را چاپ، کامیت یا در فایلی داخل مخزن ذخیره نکنید. APK و keystore هم کامیت نمی‌شوند.
5. فقط مرحلهٔ تأییدشده را انجام دهید؛ از گسترش بی‌جای کار پرهیز کنید. اگر تصمیمی اشتباه به نظر می‌رسد، **قبل از پیاده‌سازی** بگویید.
6. سازگاری با دادهٔ قبلی: هر تغییر دیتابیس فقط با Migration جدید + تست ارتقا.
7. با کاربر **فارسی و ساده** صحبت کنید؛ او مبتدی است و کامپیوترش ضعیف است — ساخت را روی ماشین خودتان انجام دهید و فقط فایل نهایی را تحویل دهید.
8. فایلی را که تغییر ذخیره‌نشده دارد با `git checkout` برنگردانید.
9. بعد از هر نسخه `PROGRESS.md`، `AGENT_NOTES.md` و همین README (جدول نسخه‌ها) را به‌روز کنید.
